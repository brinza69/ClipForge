# AI Stream Clipper map — `server/workers/` and `server/routers/`

Part of the clipper map; start at [`docs/clipper-map.md`](../clipper-map.md).

## `server/workers/` — orchestration, DB-aware

| file | what |
|---|---|
| `clipper_pipeline.py` | ingest, transcribe, analyze; registers all six handlers |
| `clipper_analysis_publish.py` | OW1: the ONLY way an analysis becomes the project's. `capture` takes the identity from the queue's claim (`CLAIMED_ATTEMPT`) and only validates it against the row — no claim → refused before any write (OW1r2 R1); `write_generation` (off the loop); `publish`: input re-check outside the lock, then one `BEGIN IMMEDIATE` that refuses a non-running / cancelled / foreign-owner / other-attempt / expired-lease job, a superseding ingest/transcribe/analyze row and a re-publication, then sets the pointer and adds the pinned `clipper_score` together. `publish_protected` + `Outcome`: the caller's cancel waits for the operation; only a publication whose COMMIT was never sent may be deleted (OW1r2 R2) |
| `clipper_build.py` | the scoring stage end to end; refines boundaries via `clipper_boundary_pass.refine_off_loop` |
| `clipper_boundary_pass.py` | `refine_off_loop`: the boundary refinement of every candidate in a worker thread with the run's own `SpeechAudio` and no DB session; cooperative stop between candidates and VAD phases, a stop is `JobCancelledError` (EN2 R3: off the event loop the heartbeat shares). Also `_record_completeness` (R5 boundary view), moved whole out of `clipper_build.py` (EN1) |
| `clipper_judging.py` | running the judge over pools of moments: which get asked about, how many rounds, and the verdict propagated to every cut of a judged moment. S7c loads and checkpoints each raw judge round; failure to write the optional checkpoint is recorded but cannot recast an already applied verdict as a judge failure |
| `clipper_cache.py` | the artifact-specific recipes consumed by the common reasoning envelope: source/transcript identity, exact upstream artifacts, service/prompt versions, resolved provider models, temperature, context window, timeout, engine order, chunk plan and local parameters. S7a covers atoms, promises, threads, the newly persisted `episodes.json`, anchors and per-stretch content types; S7c adds the judge provider contract while each round binds its exact prompt. A legacy checkpoint without the envelope is a miss, not evidence |
| `clipper_finalize.py` | everything after the winners are chosen: layout + caption planning, headlines, the two trace artefacts, the `clips` rows, and auto-export. S7f stamps every fresh row with the same `selection_run_id` as both trace artefacts and refuses a shadow rank from another run before replacing the board; preserved exports keep the run that created them. Split out when Batch 0 took `clipper_build` past 500 lines; re-exported from there. **Since 2026-09-24 a rescore keeps every clip a person worked on, not only exports:** `_kept_clips` is the ONE predicate (exported, or a `HUMAN_WORK_EVENTS` feedback row with origin manual or NULL — legacy rows predate the column, and an unreadable origin must not make an edit deletable), used by both the pre-dedupe spans and `_write_clips`, because filtering only at write time once shrank 8 winners to 3. Rejected clips are kept on purpose (reversible: drop `rejected` from the tuple). Kept rows are never written, so they keep their old run's rank; `_auto_export` skips them, since before this rule no such clip could be on the board at that point **Master plan B1/Bfix:** `_keeps()` is the one condition (exported, `exporting`, a person's work, or a system `export_invalidated`), evaluated by the rescore's DELETE itself so the protection holds at delete time; `_auto_export` claims each clip before queueing it |
| `clipper_scoring.py` | one run's candidates, scored: feature extraction, the local content verdict with its confidence and provenance, the heuristic score, and the optional blend with the learned ranker. Split from `clipper_build.py` when R2's propagation pushed it past 500 lines |
| `clipper_captions.py` | the caption track for one render: source-clock words, render-time UI placement refined around local face proposals, and the ASS burned after time remapping. Manual positions and suppression remain authoritative. Split from `clipper_render_plan.py` at 500 lines and re-exported from it. Since D2 also `_plan_for_render`: an unplanned clip (alternatives — `_write_clips` stores plans only for winners and shadow picks) gets its caption plan built at render time under `burn`, with `build_caption_plan` and the regenerate arguments, never stored (the render sees `_WithPlan`, not the row). `caption_plan_state` {origin stored|built|None, outcome burn|empty|suppressed|unavailable|empty_after_remap, reason} goes on the decision and the sidecar; `unavailable` and `empty_after_remap` also land in `clip.warnings` ("Captions not burned (reason) …"). It refuses rather than let the builder's spread invent a clock: `_window_timing` needs every word of every segment the builder reads to have a finite start and end with end >= start (a point timestamp is timing, D2r-2; a missing end, NaN, end < start or segment text with no words gives `no_timed_words` / `incomplete_timing`), and counts a word only by the builder's own word test, so a point exactly at the clip's edge never admits a window. `_write_ass(state=)` corrects `burn` IN PLACE to the effective result (`empty_after_remap` when the dead-air remap removed every event); `caption_plan` stays the intended plan. `_caption_warnings` applies a render's report to the CURRENT `clip.warnings`, labelled "Result of the last preview|export" (an edit does not clear it; the next render replaces it), and leaves any value that is not a list of str alone. `_place_burned` (reaction-fit height, then local faces) moved here from `_decide_render` at 500 lines |
| `clipper_render_plan.py` | WHAT a render will contain: window, shot list, layout, caption file, dead-air spans. `_decide_render` is the entry point and both handlers consume its one answer. It also builds R4's boundary list and clip-relative scene cuts into `_rhythm`, because the words, the scene list and the audio peaks exist nowhere else — working data, popped before the sidecar with the rest. D2: the caption policy is decided before `_caption_y`, and `_plan_for_render` supplies the plan the rest of the decision reads (494 lines after the two declared moves) |
| `clipper_shadow_views.py` | everything a render RECORDS about the edit it did not make: R3a's `creator_view`, R3b's `regime_view`, R4's `rhythm_view`. Split from `clipper_render_plan.py` in R4 at 500 lines, on the seam the batches drew themselves — that file answers WHAT to render, this answers what to say about it, and nothing here may move a delivered frame. All three share ONE clock: the hop comes from the first and is handed down, so they cannot drift into describing different timelines and then be compared as if they described one |
| `clipper_render_output.py` | Shared full-quality execution and v2 sidecar writer (2026-09-09). Normal export, replan, frozen-plan replay and camera/letterbox probes call it. One set of fps/CRF/preset/watermark/output dimensions feeds both renderer branches and the recorded recipe. Strips transient observations on a copy, captures the actual caption filter on static AND dynamic paths, and records output identity after encoding. Planning, advisory reviews, DB status and feedback remain with callers. Frozen replay refuses an undeclared caption policy instead of inferring it from a stale ASS. Real integration tests compare normal/replan MP4 bytes, decoded caption pixels and trimmed durations; this is execution verification, not editorial approval. `render_export(discard_on_cancel=)`: only the export job passes True — a cancel stops the coroutine, not the dynamic encoder's thread, which then removes the staged file it finishes; probes and the re-render scripts write the real path and keep the default The sidecar carries `end_tail`, computed after `output_identity` from the render record, the drop spans, `render.fps` and the probe; the row only detects an edit (EN3T). |
| `clipper_preview_frame.py` | Editor stills from `_decide_render` and the export command builders. Processes earlier camera commands and cuts, then selects a frame on the shared output grid in a temporary directory. Reports the selected time, delivered duration and actual caption action; never substitutes an old export for the saved edit. SCB2r: the export's gate on the still — `prepare`, then `require_corroborated` on the FINAL argv before it runs and `confirm_patch` after; a refused still leaves no image. |
| `clipper_render_jobs.py` | the export and preview jobs themselves, plus Pass D. Since 2026-09-09 full-quality execution and sidecar writing are delegated to `clipper_render_output`; preview remains the deliberate low-resolution path. The sidecar the audit reads: since R0 it carries `render_version` (whichever renderer actually ran), `input_fingerprint` (computed through `edit_quality.input_fingerprint` over the recipe only — no titles, scores or ids), `drop_spans`, `caption_y`, and the source size. S7f adds `selection_run_id` as a provenance label outside that image fingerprint; old clips remain honestly `null`. The caption plan stays STORED and the render-time height rides beside it, so the two decisions can still be told apart. R4b + review F2/F3/F6: an export attempt renders its mp4 and sidecar to `.{clip}.{job}-{rand}.mp4/.json` beside the export (the dynamic sendcmd to the same stem `.cmd.txt`) and decides its caption `.ass` into its own directory `.{clip}.{job}-{rand}/` — a shared `.ass` let a superseded attempt hand the current one its captions. `_publish_export` moves the mp4, the sidecar and, when captions were burned, the `.ass` to `{clip}.mp4/.json/.ass` under the write lock, only while the job is the clip's current, running, owned attempt; everything else is deleted in `finally`. R4c (Codex Q2/Q3): `render_record.ass_path` / `ass_path_offered` keep what the encode EXECUTED — the attempt's scratch `.{clip}.{job}-{rand}/{clip}.ass`, gone after the job, and that is expected — while `render_record.ass_published_path` names `{clip}.ass` beside the export and is written only when the argv read this attempt's `.ass`; the same `ass_sha256` binds both. With no filter no key is written and no `.ass` is published, so an older `{clip}.ass` stays. The docstring of `_publish_export` states the crash limit of its three non-atomic renames. The export applies its caption report in `_publish_export(caption_state=)` against the row as it is under the lock (D2r K3). A preview publishes the same way (D2r-2 K7): its own attempt files (`previews/.{clip}.{job}-{hex}.mp4`, its `.cmd.txt`, a scratch dir for the `.ass`), then `_publish_preview` moves the mp4 into place and writes `preview_path` and the report under `begin_write` — only while `_preview_inputs` (the caption inputs plus content type, dimensions, source file and project content type: everything the PICTURE reads) still equals what the preview loaded and no export published since. Otherwise nothing moves, the job fails "discarded", and its row gets `metadata.discarded` = `inputs_changed` | `newer_export` (D2r-3), which the card reads — never the error text SCB2: `_publish_export` refuses a treated sidecar (`refuse_treated_publish`); `handle_preview` runs `source_treatment_render.prepare` on the decision it draws, in its attempt's own scratch, and hands `source_patch` to both renderers (codex-verdict-next-24 §2 — before it, a treated clip previewed its untouched source text). |

Not clipper: `remix_pipeline.py`, `parallel_pipeline.py`, `doodle_pipeline.py`,
`utility_jobs.py`.

| `clipper_preview_publish.py` | BURST R1/R1b/R1c: where a preview's file is published and which ATTEMPT it belongs to. `attempt_path` = `<clip>.<job>-a<attempt>.mp4`, immutable, never a selected file's name. `_publish_preview` selects it, `preview_path` AND `clips.preview_record` `{job_id, attempt, worker, caption_plan_state}` in ONE transaction under the write lock, only while the job row is still this attempt's (running, same worker and `attempt_count`, a live lease), the picture's inputs are unchanged, no export published and no later attempt is selected; else `newer_preview`/`inputs_changed`/`newer_export`, or `attempt_not_current` (`LOST_ATTEMPT`, no marker on a row that is no longer this attempt's). `capture_attempt` is the attempt the queue CLAIMED for this invocation (`job_attempt.CLAIMED_ATTEMPT`), never the row read later. `handle_preview` (re-exported by `clipper_render_jobs`) refuses to render without it and deletes its own file only when it is not the selected one |

## `server/routers/`

`clipper.py` (projects, settings, artifacts) and `clipper_clips.py` (clip-level
operations). Split to stay under the 500-line limit.
`clipper_reaction.py` adds source-frame reading and save/clear of per-clip reaction
regions; it shares the ordinary layout, caption and export paths.
`clipper_caption_source.py` is `PUT /clips/{id}/caption-source`: a person's per-clip
answer to whether the source already shows burned subtitles (true / false / null),
read by `caption_policy.decide` at both decision sites. An answer that turns the layer
ON runs the reaction PUT's own caption check first: a reaction framing saved while
the layer was off may leave no caption slot, and accepting it would fail every later
preview and export, so it is a 422 with `max_content_height`. The answer is recorded
as a manual `caption_changed` event, so a rescore keeps the clip (`clipper_finalize`).
The PROJECT answer (master plan B2): PATCH `/projects/{id}/settings` with only
`source_has_burned_captions` changed re-scores nothing; `apply_project_answer` checks every inheriting clip
under one `BEGIN IMMEDIATE` (409 while one is exporting, 422 with `blocking_clips` when a reaction framing
leaves no caption slot, zero writes on refusal) and writes a system `export_invalidated` for each export it clears.
`clipper_source_treatment.py` is `GET`/`PUT /clips/{id}/source-treatment` (SC3): per clip, `{source_caption_treatment: null | none | blur+mask_sha256, caption_layer: null | burn | suppress}`, replaced together; strict types, erase refused, the mask named by hash and validated from the store, `decided_by` the server's; a real change invalidates the render in the same transaction, the same configuration again writes nothing, 409 while exporting. `handle_export` publishes a blur-only treatment through its own staged file (`PUBLISH_BLUR`) and `_publish_export` (`refuse_treated_publish(blur=True)`); erase never. The older policy routes (`clipper_caption_source`, the reaction PUT) decide with the clip's `caption_layer`: only clips whose effective action flips are moved, a chosen burn without a blur that an answer would put over source text is refused, and a reaction framing is refused on a clip that blurs the source (static path).
`clipper_review.py` also answers which runs can be reviewed blind (master plan B3): GET `/review/cohorts?project_id=` lists each scoring run with its counts, media validity and eligibility or named reasons, and the session POST accepts `selection_runs` (every picked project names one eligible run; a partial map is refused).
`clipper_clips.py` `/clips/{id}/export-file` serves only an `exported` clip (R4c): 404 `no_export` without an `export_path`, 409 `export_not_current` while a re-export runs, after a failed, cancelled or recovered attempt, or for a half-published set. PATCH `warnings` must be a list of str or null (400 `invalid_warnings`, D2r K4). `GET /clips/{id}` answers the board's card shape through `project_attempts.clip_cards`, so it carries `last_preview`; the other clip responses do not, and the board re-reads rather than merging them (D2r-3).
